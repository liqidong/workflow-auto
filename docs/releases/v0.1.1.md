# v0.1.1

## What this release is

`v0.1.1` is a small follow-up release after `v0.1.0`.

It captures the execution-quality guardrails that were intentionally added as
execution constraints without changing GOI routing, OpenSpec, `gstack`, review,
or QA.

## What is included

- execution-quality guardrails for implementation, debugging, hardening,
  review-finding fixes, and blocker fixes
- canonical `.agents/skills/goi-workflow/SKILL.md` reference to the execution
  quality guardrail surface
- workflow README, checklist, and verifier updates that include
  `docs/ops/workflow/execution-quality.md`
- pytest contract coverage for the execution-quality guardrail surface

## How to verify locally

Run:

```text
scripts/check-host-workflow-deps.sh
scripts/verify-workflow-template.sh
./.venv/bin/pytest -q
openspec validate --specs
```

## How to copy or adopt the template

1. Copy the reusable template surfaces into the new repository.
2. Replace the host-specific identity in `README.md`.
3. Replace the current-mainline inventory in
   `openspec/specs/project-mainline-routing/spec.md`.
4. Keep `.agents/skills/goi-workflow/SKILL.md` canonical.
5. Keep `.codex` and `.claude` GOI entries as thin shims only.
6. Run the local verification chain before treating the copied repo as ready.

## Known residual risks

- The workflow still emits a GitHub-hosted warning about Node.js 20-based
  action runtimes; those action majors may need future updates before GitHub's
  enforced runtime change.
